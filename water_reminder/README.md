# 喝水提醒

无需构建或账号的 Chrome Manifest V3 扩展。设置每日饮水目标、提醒时段和多段休息时间。每杯喝完后手动确认；未确认每 5 分钟再次提醒，并重排后续时间和剩余水量。设置及饮水记录只保存在本机。

## 安装和使用

1. 打开 `chrome://extensions/`，开启「开发者模式」。
2. 点击「加载已解压的扩展程序」，选择本目录 `water_reminder`。
3. 固定「喝水提醒」到工具栏，点击水滴图标。
4. 设置每日目标、开始时间、结束时间和休息时间，开启提醒并保存。
5. 收到提醒后喝完指定水量，再点击「已喝完」确认。

默认计划为 **2000 ml，09:00–18:00**，每天重复，无需每天重新开启。修改开关也需保存。

## 手动确认、重复催促与重排

- **发送通知不代表已喝。** 只有手动确认才将当前杯的毫升数计入已确认量。
- 可在网页动画、插件面板点击「已喝完」；系统通知中可点「已喝完」按钮，也可喝完后直接点击通知正文确认。关闭系统通知不会确认。
- 每次只有一杯待确认水，不把几杯叠加成大杯。未确认时每 **5 分钟**重新发送同一杯，当前杯水量保持不变。
- 每次催促以当前时点重排其余计划；确认后从**实际确认时间 +30 分钟**开始安排下一杯，将剩余目标均分到结束时间之前的有效提醒时点，并避开休息。
- 例：09:30 提醒后未确认，09:35 再提醒同一杯；09:37 确认后，下一次为 10:07，末次仍对齐结束时间。等待越久，剩余次数可能减少，每次计划水量随之重新计算。
- 重复点击同一杯只记录一次。浏览器重启、Worker 休眠后仍保留待确认、已确认水量和重试闹钟。
- 「当前剩余计划」展示动态安排；下面的「完整饮水计划」是表单设置的初始计划预览。
- 暂停会停止催促并保留记录，暂停期间仍可在插件面板确认；恢复后继续当前杯的催促并重排余下计划。
- 修改目标不会抹掉本轮确认记录；目标不能低于已确认量与当前待确认杯之和。
- **结束时间后停止催促**，保留本轮待确认状态，仍可手动确认。到下一轮开始时间记录上一轮完成情况并启用新目标；未确认的水量不会自动计入，也不会叠加到下一天。
- 点击「发送测试通知」只测试显示，需手动点「确认测试提醒」关闭；测试不记饮水量，也不会开启重复催促。

## 休息时间

展开「休息时间，不提醒」，可添加、删除多段时段，保存后生效。

- 休息开始时间包含在内，结束时间不包含在内；支持跨午夜、重叠休息。
- 初始计划例如 09:00–18:00、2000 ml，设置 12:00–13:00 午休后，共 16 次，每次 125 ml。
- 首次提醒、后续计划及 5 分钟催促都避开休息；催促落入休息时，等到休息结束再继续。
- 若休息覆盖全部初始提醒，则提示调整并拒绝保存。

## 网页动画提醒

1. 开启「网页动画提醒」，保存并在 Chrome 提示中允许网页权限。
2. 打开普通 HTTP / HTTPS 网页，再点击「发送测试通知」验证。

提醒会在最后聚焦的 Chrome 窗口当前网页右下角显示哆啦 A 梦捧水杯的透明插画，并轻轻晃动。卡片**不会自动消失**，也不能用 Escape 跳过，须手动确认；当前待确认卡片可被同一杯的下一次催促替换。确认成功后清理相关网页卡片。系统开启减少动态效果时显示静态角色。

动画默认关闭，网页权限按需授权。角色素材已打包到插件中，不读取网页内容、不请求外部网络。Chrome 内置页面、扩展页面、商店等受限页面、未授权或隐藏的网页无法显示动画，仍可使用系统通知和插件面板。系统通知权限关闭时，网页动画可独立显示。

## 初始分配与时间规则

- 提醒从开始时间 30 分钟后发出，最后一段不足 30 分钟则对齐结束时间；少于半小时的时段仅在结束时提醒一次。
- 所有水量均为整数毫升，余数分配到前几杯；在剩余时段有可用提醒时，已确认、待确认及剩余计划合计等于目标。没有可用时点的水量会保留为未完成量。
- 支持跨午夜，例如 23:00–01:00 属于同一饮水日，到下一次 23:00 才开启新一轮。
- 目标范围为 1–20000 ml，且至少等于初始有效提醒次数；开始和结束不能相同。
- 时段中途安装、保存或恢复时按剩余时段安排剩余目标；不会将旧版本的「提醒已发送」自动记作「已喝」。
- 结束时仍未完成的目标保留为未完成量，不强制要求一次喝完。

## 后台与通知

使用 `chrome.alarms` 驱动提醒，关闭弹窗继续运行。Chrome 完全退出、电脑关闭或休眠期间无法显示通知。恢复后同一杯最多补一次提醒，继续 5 分钟催促，不集中补发多杯。Chrome 闹钟可能延迟，参见 [Chrome alarms 文档](https://developer.chrome.com/docs/extensions/reference/api/alarms)。

网页卡片会一直等待手动确认；系统通知请求保持显示，但操作系统的通知样式和专注模式仍可能让它收起。收起或关闭不会计作确认，催促继续。macOS 可在「系统设置 → 通知 → Google Chrome」检查通知权限和样式。

使用电脑本地时间；修改系统时间、时区或夏令时切换后请重新保存计划。权限包括 `storage`、`alarms`、`notifications`、`scripting`，网页访问权限可选。

## 开发验证

Node.js 18 或更新版本，无第三方依赖，在仓库根目录执行：

```sh
node --test water_reminder/tests/*.test.mjs
```

测试覆盖时间与整数分配、跨午夜、多段休息、确认去重、5 分钟催促、重排、目标修改、暂停与恢复、Worker 重启、结束边界、通知失败及动画兜底。

浏览器验证可设置短时段，检查首次通知进入待确认、面板与网页确认、重新发送同一杯，以及确认后闹钟变更。测试通知不会改变实际饮水记录。
